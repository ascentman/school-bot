# Бот обліку харчування учнів

Telegram-бот для школи: щобудня о 08:00 питає класних керівників, скільки дітей
харчується, записує відповіді в базу і показує їх перевірці — Google-таблицею,
що оновлюється сама, або звітом XLSX/PDF.

Створено для роботи соціального педагога.

---

## Що вміє

**Збір даних**
- **09:05** — запит класним керівникам (Пн–Пт, крім канікул і свят).
- Відповідь — **дотик по цифрі**: сітка центрується на значенні попереднього
  навчального дня, тому потрібна цифра майже завжди вже на екрані.
- Після харчування бот питає ще двічі: **«Всього відсутніх»** і **«З них по
  хворобі»**. Третє питання ставиться, лише якщо відсутні є; будь-яке з двох
  можна пропустити кнопкою «⏭ Пропустити» — цифра харчування вже збережена.
  Якщо відсутніх більше, ніж є на сітці (карантин), поруч є «✏️ Інша цифра».
  Хворих не буває більше за відсутніх: стеля перевіряється на сервері, і при
  зменшенні відсутніх цифра хворих підрізається разом із нею.
  Пропущене лишається порожнім і у звіті показане як «—», а не як нуль.
- **09:15 і 09:30** — нагадування тим, хто не відповів.
- **09:40** — звіт про харчування: класи за змінами роздачі й цифри.
- **09:50** — звіт про відсутніх і хворих.

Обидва йдуть адміністраторам у Telegram і на пошту. Звіти окремі, бо їх читають
різні люди: харчування несуть на кухню, відсутніх — медсестрі. Хто не подав
дані, видно в тексті до звіту й на кнопці «📊 Сьогодні» — там же кнопки, щоб
ввести за них.
- Кожна правка потрапляє в журнал: хто, коли, яку саме цифру, з якого
  значення на яке.
- **Переживає блекаути**: якщо сервер лежав о 09:05 і піднявся о 10:20, бот
  догоняє пропущену розсилку при старті — рівно один раз.

Часи задаються в `.env` (`PROMPT_TIME`, `REMIND_TIMES`, `DIGEST_TIME`).
Нагадувань може бути скільки завгодно — просто перелічіть через кому.

**Звітність**
- Google-таблиця: вкладка на місяць (класи × дні), вкладка «Зведення» по місяцях.
  Оновлюється автоматично. Доступ «за посиланням — перегляд» — відкрили з телефону,
  показали перевірці.
- XLSX і PDF за місяць — з бота однією кнопкою. Метрик три, тож у книзі три
  аркуші («2026-09», «2026-09 відсутні», «2026-09 хворі»), а в PDF — три
  сторінки. Аркуш харчування лишився таким, як був: у ландшафтній таблиці на
  31 день колонка вже ~8 мм, тож третю цифру в клітинку не вкласти.
  Google-таблиця так само дістає три вкладки на місяць.
- Вихідні — сірим, канікули — жовтим, пропущені навчальні дні — червоним.
  Майбутні дати пропусками не вважаються.
- **PDF про харчування** — рівно **один аркуш А4** і найбільший кегль, який на
  ньому вміщається: звіт читає людина старшого віку, часто роздрукований.
  Дві колонки поруч, розріз лише по межі зміни, щоб роздача не розʼїжджалася.
  Кегль підбирається сам, тож більша школа дасть менший шрифт, а не другу
  сторінку — її просто не понесуть на роздачу.
- **PDF про відсутніх** — так само один аркуш: ті самі зміни роздачі, дві
  колонки цифр (відсутні й з них хворі). Кегль трохи менший за звіт про
  харчування, бо колонок більше.
  (`08:45 – 09:00`, `09:15 – 09:30`, …), у тому порядку, в якому діти йдуть до
  їдальні. Приходить сам о 09:40 і на кнопку `📊 Сьогодні`. Школа на 25 класів
  вміщається на один аркуш; клас, що не подав цифру, показаний як «—» і в суму
  не входить.

Розклад роздачі задається в `.env` (`MEAL_SLOTS`), зміни через `;`, класи
всередині зміни — через кому:

```
MEAL_SLOTS=08:45-09:00 = 3-А, 3-Б; 09:15-09:30 = 6-А, 6-Б, 10-Б
```

Клас, не згаданий у `MEAL_SLOTS`, не зникає — він іде в кінець звіту групою
«Поза розкладом». Якщо `MEAL_SLOTS` не заданий, PDF — простий перелік класів.

**Звіти на пошту.** Ті самі PDF о 09:40 і 09:50 надсилаються на адреси з
`REPORT_EMAILS`; головні цифри дублюються в тілі листа, щоб відповісти
«скільки сьогодні?» не відкриваючи вкладення. Канал необовʼязковий: без
`SMTP_*` бот працює як раніше, лист просто не йде. Недоступний SMTP не зриває
звіт у Telegram — помилка лишається в логах.

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=вашa@gmail.com
SMTP_PASSWORD=<App Password, 16 символів>
REPORT_EMAILS=dyrektor@school.ua, buhgalter@school.ua
```

Для Gmail потрібен саме **пароль додатка**: увімкніть 2FA і створіть його на
<https://myaccount.google.com/apppasswords> — звичайний пароль від скриньки
Google відхилить. Вставляти можна прямо як показує Google, групами по
чотири: пробіли (зокрема нерозривні) прибираються самі.
Для SMTPS (порт 465) поставте `SMTP_SSL=true`.

Перевірити налаштування, не чекаючи ранку:

```bash
uv run school-bot day-report --email
```

**Адміністрування з бота**
- Вчителі гуртом: `/import_teachers` — вставили список «ПІБ, телефон, класи»,
  бот розібрав і створив разом з класами. Повторний імпорт оновлює, не дублює.
- Класи вчителя редагуються будь-коли (`/edit_teacher`), класи, канікули діапазоном.
- Стороннім бот не відповідає.

## Запуск

### 1. Створити бота

Напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → отримайте токен.

Свій Telegram ID дізнайтеся у [@userinfobot](https://t.me/userinfobot) — він
знадобиться, щоб отримати права адміністратора.

### 2. Налаштувати

```bash
cp .env.example .env
```

Заповніть у `.env`:

```ini
BOT_TOKEN=123456:ABC-DEF...
SCHOOL_NAME=Ліцей №1 м. Львова
BOOTSTRAP_ADMINS=123456789          # ваш Telegram ID
SCHOOL_CLASSES=1-А,1-Б,2-А,3-Б      # усі класи школи
```

`SCHOOL_CLASSES` створюються при старті, і саме з них вчитель обирає свої під
час реєстрації. Клас, прибраний зі списку, не видаляється — за ним лишається
історія записів; сховати його з опитування можна командою `/off_class`.

### 3. Запустити

**Docker (рекомендовано):**

```bash
docker compose up -d --build
docker compose logs -f bot
```

**Локально:**

```bash
uv sync
uv run alembic upgrade head
uv run school-bot run
```

### 4. Наповнити

У Telegram: `/start` → ви отримаєте меню адміністратора.

**Вчителі — гуртом.** `/import_teachers` і вставте список:

```
Коваленко Марія Іванівна, 0671234567, 1-А
Шевчук Оксана Петрівна, 0509876543, 3-Б, 5-В
Мельник Ігор Богданович, 0631112233
```

Порядок колонок не важливий — номер і клас бот упізнає сам. Розділювач: кома,
крапка з комою або табуляція, тож список можна просто скопіювати з Excel. Класи
створюються автоматично; вказувати їх не обовʼязково.

Далі надішліть усім **одне посилання** — `t.me/ваш_бот`. Кожен натисне «Почати»,
поділиться номером, і бот сам знайде його у списку разом з класами.

**Решта:** `🗓 Неробочі дні` → `/days_off` → `28.10.2026 - 03.11.2026`.

Готово. Наступного робочого дня о 09:05 вчителі отримають перший запит.

## Як спробувати за 10 хвилин

Хостинг для цього не потрібен: бот працює через long polling, тобто сам
підключається до Telegram. Запуститься з ноутбука за NAT, без білого IP і
сертифіката.

### 1. Отримати токен і свій ID

- [@BotFather](https://t.me/BotFather) → `/newbot` → назва → username → **токен**
- [@userinfobot](https://t.me/userinfobot) → напишіть будь-що → **ваш numeric ID**

### 2. Створити `.env`

```bash
cp .env.example .env
```

Замініть у ньому два рядки на свої:

```ini
BOT_TOKEN=<токен від BotFather>
BOOTSTRAP_ADMINS=<ваш ID від userinfobot>
```

### 3. Підготувати базу

```bash
uv sync
uv run alembic upgrade head
uv run school-bot link --tg-id <ваш ID> --name "Ваше ПІБ" --classes "1-А,3-Б" --admin
```

Остання команда одразу створює класи, робить вас адміністратором **і** класним
керівником — інакше запити приходили б комусь іншому, і перевірити потік було б
ніяк.

### 4. Запустити

```bash
uv run school-bot run
```

У логах має зʼявитися `Бот @ваш_бот запущено` і список джобів.

### 5. Пройти сценарій

У Telegram знайдіть свого бота → `/start`.

| Що зробити | Що має статися |
|---|---|
| `/start` | Меню адміністратора |
| В іншому терміналі: `uv run school-bot prompt --force` | Прилітають запити по ваших класах із сіткою цифр |
| Тапнути цифру | Повідомлення міняється на «✅ записано», зʼявляється «Виправити» |
| «✏️ Виправити» → інша цифра | Значення оновлюється |
| `📊 Сьогодні` | Зведення: хто подав, хто ні, разом — і PDF за день |
| `uv run school-bot remind --force` | Нагадування лише по класах без відповіді |
| `📅 Звіт за місяць` | XLSX і PDF у чат |
| `🗓 Неробочі дні` → `/days_off` → `01.09.2026 - 05.09.2026` | Дні позначено; у звіті вони жовті |

`--force` потрібен, щоб не чекати 09:05 і щоб працювало у вихідний.

### 6. Перевірити стійкість до блекауту

```bash
# зупинити бота (Ctrl+C), потім:
uv run school-bot status      # видно, що дані за сьогодні не зібрані
uv run school-bot run         # при старті бот сам догоняє пропущену розсилку
```

У логах має бути `Догоняю пропущений джоб prompt`. Перезапустіть ще раз —
повторів бути не повинно.

### Прибрати тестові дані

```bash
rm -rf data/ && uv run alembic upgrade head
```

## Google Sheets (необовʼязково)

Без цього кроку бот працює — просто немає авто-таблиці, звіти доступні файлами.

1. [Google Cloud Console](https://console.cloud.google.com/) → новий проєкт →
   увімкнути **Google Sheets API**.
2. **IAM & Admin → Service Accounts** → створити → **Keys → Add key → JSON**.
3. Покласти файл у `secrets/service-account.json`.
4. Створити Google-таблицю, скопіювати ID з URL
   (`docs.google.com/spreadsheets/d/`**`ЦЕ_ID`**`/edit`).
5. Поділитися таблицею з e-mail сервісного акаунта (з JSON, поле `client_email`)
   з правами **Редактор**.
6. У `.env`:

```ini
GOOGLE_CREDENTIALS_FILE=./secrets/service-account.json
GOOGLE_SHEET_ID=1AbC...
```

7. У боті: `/sync`.

Щоб показувати перевірці — у таблиці **Доступ → Усі, хто має посилання →
Переглядач**.

## CLI

Щоб перевіряти роботу, не чекаючи 08:00:

```bash
uv run school-bot status                       # класи, вчителі, стан на сьогодні
uv run school-bot seed                         # демо-дані для перевірки
uv run school-bot prompt --date 2026-09-02     # розіслати запит зараз
uv run school-bot prompt --force               # надіслати навіть у вихідний
uv run school-bot remind                       # нагадування боржникам
uv run school-bot meals-report                 # звіт про харчування
uv run school-bot absence-report               # звіт про відсутніх
uv run school-bot report --month 2026-09 --fmt both
uv run school-bot sync-sheets --month 2026-09
uv run school-bot backup                       # копія БД (тримає останні 30)

uv run school-bot link --tg-id 123 --name "ПІБ" --classes "1-А" --admin
uv run school-bot import-teachers spysok.txt   # той самий імпорт, але з файлу
```

`link` створює або оновлює вчителя напряму, без інвайт-посилання — для
початкового налаштування й на випадок, якщо вчитель загубив запрошення.

## Архітектура

```
src/school_bot/
├── config.py        конфіг із .env
├── cli.py           ручний запуск джобів, seed, бекап
├── db/              моделі та сесії
├── domain/          календар, облік, розбір класів і дат
├── bot/             хендлери, клавіатури, тексти, middleware
├── scheduler/       джоби 09:05 / 09:15 / 09:30 / 09:40 / 09:50 / 20:00
└── reports/         matrix → xlsx / pdf / sheets
```

Два принципи, на яких тримається код:

**`domain/` і `reports/` не імпортують aiogram.** Уся Telegram-специфіка живе в
`bot/`. Тому логіка тестується без мережі, а якщо колись знадобиться інший канал
(веб-форма, інший месенджер), переписувати ядро не доведеться.

**Метрика — параметр матриці, а не окремий код.** `build_month_matrix(...,
metric=...)` проєктує потрібну колонку, і три аркуші — це три `MonthMatrix`,
які малюють ті самі рендерери. Червоним підсвічується «клас того дня не подав
нічого», а не «цієї цифри немає»: інакше аркуш «Відсутні» був би суцільно
червоний на всій історії до появи фічі.

**Усі місячні експорти будуються з однієї `reports/matrix.py`.** XLSX, PDF і
Google Sheet не можуть розійтися між собою, а новий формат додається в одному
місці. Щоденний звіт має власну структуру (`reports/day.py`): він відповідає на
інше питання — не «як було протягом місяця», а «кого й скільки годувати зараз»,
і групується не по класах, а по змінах роздачі.

**БД — джерело правди, Google-таблиця — дзеркало.** Будь-яку вкладку можна
перебудувати з нуля (`school-bot sync-sheets`), тому зіпсована вручну таблиця
не є втратою даних.

## Стійкість до простою

Cron не відтворює минуле: якщо сервер лежав о 09:05, запланований запит того дня
просто не відбудеться — мовчки, поки хтось не помітить дірку в звіті. Для
хостингу в Україні це не крайній випадок.

Три рівні захисту:

1. **`misfire_grace_time` = 2 год** замість дефолтної 1 секунди APScheduler.
   Коротка затримка (завантажений сервер, перезапуск) більше не зʼїдає розсилку.
2. **Догоняюча розсилка при старті** (`jobs.catch_up`) — бот дивиться, які
   розсилки за сьогодні мали відбутися й не відбулися, і виконує їх.
3. **Журнал запусків** у таблиці `app_setting` — тому перезапуск процесу десять
   разів поспіль нічого не продублює.

Догоняння не працює після `CATCH_UP_DEADLINE` (типово 15:00): запит про
сьогоднішнє харчування о 19:00 уже безпредметний.

## Що бачить вчитель

Свідомо мінімум — вчитель має закрити задачу кількома дотиками, а не вивчати бота.

| Команда / кнопка | Що робить |
|---|---|
| `/start` | Вітання і меню |
| `📋 Мої класи` або `/today` | Класи зі станом на сьогодні; звідси можна ввести або змінити цифру |
| `/help` | Коротка інструкція |
| Кнопки в ранковому запиті | Цифра, «Інша цифра», «Виправити» |

Адмінських команд вчитель **не бачить**: меню виставляється персонально через
`BotCommandScopeChat` при кожному `/start`. Виправити дані за минулі дні вчитель
не може — лише адміністратор, і кожна така правка потрапляє в журнал.

`/today` існує тому, що інакше єдиний шлях подати цифру — кнопки в ранковому
повідомленні. Видалив його або не помітив — і ввести нічим.

## Як вчителі потрапляють у бота

Bot API **не дозволяє знайти людину за номером телефону** і не дозволяє боту
написати першим. Тому реєстрацію завжди ініціює сам вчитель. Є два шляхи:

**Гуртом (основний).** Адміністратор завантажує список «ПІБ, телефон, класи»
через `/import_teachers` і надсилає всім одне спільне посилання на бота. Вчитель
відкриває, тисне «📱 Поділитися номером» — бот зіставляє номер зі списком і
привʼязує акаунт разом з класами. Персональні запрошення не потрібні.

Номери нормалізуються, тож `067 123-45-67`, `+380671234567` і `0671234567` —
це той самий вчитель.

**Номера немає у списку — не біда.** Бот зареєструє людину сам, спитає ПІБ
і запропонує обрати свої класи зі списку школи (`SCHOOL_CLASSES` у `.env`):
спершу один, потім «➕ Ще один клас» або «✅ Це все».
Списку працівників він не звіряє: новий працівник, інший номер чи помилка
в імпорті інакше впиралися б у відмову й пошук адміністратора. Класів у такої
людини немає, доки їх не призначать через `/edit_teacher`, тож запитів вона
не отримує й нічого не бачить.

Захист від чужого контакту лишається: Telegram дозволяє надіслати боту контакт
з адресної книги, тому бот звіряє `user_id` у контакті з відправником.

**По одному.** `/add_teacher` створює одноразове посилання
`t.me/бот?start=inv_xxx` для конкретної людини. Зручно, коли протягом року
доходить один новий працівник.

У списку `👩‍🏫 Вчителі` видно, хто ще не відкрив бота: поки вчитель цього не
зробив, запити йому фізично не надходять.

## Розгортання на сервері

`deploy/setup.sh` розгортає бота на чистій Ubuntu. Перевірено на 1gb.ua
(Hyper-V, 1 ГБ RAM, Франкфурт), працює від 512 МБ.

```bash
ssh-copy-id root@СЕРВЕР
scp deploy/setup.sh root@СЕРВЕР:/root/
ssh root@СЕРВЕР 'bash /root/setup.sh'

# Секрети — окремо, у git їх немає і бути не повинно
scp .env root@СЕРВЕР:/opt/school-bot/.env
scp secrets/service-account.json root@СЕРВЕР:/opt/school-bot/secrets/
ssh root@СЕРВЕР '
  chown bot:bot /opt/school-bot/.env /opt/school-bot/secrets/service-account.json
  chmod 600 /opt/school-bot/.env /opt/school-bot/secrets/service-account.json
  systemctl start school-bot'
```

Скрипт ідемпотентний — повторний запуск оновлює код, залежності й
перезапускає службу, нічого не ламаючи. Розгорнути іншу гілку:
`BRANCH=feat/щось bash /root/setup.sh`.

Порт SSH визначається зі `sshd -T`, а не зашитий: якщо ви перенесли SSH
на нестандартний порт, файрвол не замкне вас назовні. Бот працює від непривілейованого користувача `bot`, автоматично
підіймається після збою й після перезавантаження, щоночі о 03:00 робить
копію бази.

Спожиток: **~240 МБ**, пік під час генерації звітів — близько 280 МБ.

### Три граблі, на які ми наступили

**Емульований дисковод вішає apt.** `blkid` намагається прочитати
неіснуючий `/dev/fd0` і застрягає в незупинному стані; udev щохвилини
запускає новий, load average доходить до 30, а `apt` стоїть годину без
руху. Скрипт блокує драйвер до першого `apt`.

**`apt upgrade` замало.** Він не встановлює нові пакети, тож оновлення
ядра лишається незастосованим — і `do-release-upgrade` потім відмовляється
працювати. Потрібен `full-upgrade`.

**Служба не повинна викликати `uv`.** `uv` пише кеш у домашню теку, яку
`ProtectHome=read-only` закриває, і служба падає по колу. Запускається
готова точка входу `.venv/bin/school-bot`.

## Чому Telegram, а не Viber

Viber-боти, створені після 05.02.2024, тарифікуються Rakuten Viber: **€100/місяць**
абонплати плюс оплата за кожне повідомлення, ініційоване ботом. Щоденна ранкова
розсилка — саме ця категорія, тобто ~€1200/рік. Telegram надає те саме безкоштовно
й без обмежень.

Якщо школа має Viber-бота, створеного **до** 05.02.2024, він працює безкоштовно —
тоді Viber можна додати як другий канал: доменний шар від месенджера не залежить.
